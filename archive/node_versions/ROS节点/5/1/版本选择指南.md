# RL推理节点版本选择指南

## 版本总览

你现在拥有**四个版本**的RL推理节点：

| 版本 | 文件大小 | 参数数量 | 核心功能 | 推荐场景 |
|------|---------|---------|---------|---------|
| **v21** | 基线 | ~10 | 基础控制 + 目标角门控 | 空旷环境，追求稳定性 |
| **v22** | 55KB | ~25 | v21 + 近目标收束 + 绕圈保护 | 只有近目标绕圈问题 |
| **v23** | 42KB | ~20 | v21 + 前向障碍绕行 | 只有障碍前蹲步问题 |
| **v24** | 40KB | ~35 | v22 + v23 完全合并 | **两个问题都有（推荐）** |

## 详细对比

### v21 (基线版本)

**优势**：
- ✅ 空旷环境直行最稳定
- ✅ 代码简洁，参数少，易调试
- ✅ 计算开销最小
- ✅ 纯网络控制，无规则干预

**劣势**：
- ❌ 近目标时可能绕圈
- ❌ 障碍物前可能蹲步
- ❌ 缺乏特殊场景保护机制

**适合**：
- 训练环境与部署环境高度一致
- 场景简单，障碍物少
- 追求极致直行性能

---

### v22 (近目标收束版)

**新增功能**：
1. 三级梯度减速（1.0m / 0.7m / 0.6m）
2. 精确对准模式（P控制）
3. 防大弧线组合（速度-角速度联合限制）
4. 绕圈保护器（12帧滑动窗口检测）

**解决问题**：
- ✅ 快到目标点时绕圈
- ✅ 长期单侧转向
- ✅ 距离下降缓慢

**日志标签**：
- `near_goal_stage_1/2`
- `near_goal_align`
- `orbit_guard_align`

**适合**：
- v21在近目标绕圈
- 需要更精确的到达控制
- 目标点周围有一定空间

**参考文档**：`rl_planner_v22_README.md`

---

### v23 (障碍绕行增强版)

**新增功能**：
1. 前向障碍检测（最新帧激光）
2. 左右通道比较（动态方向选择）
3. 两级保护机制（软/硬阈值）
4. 最小转向保证（防止角速度不足）

**解决问题**：
- ✅ 在障碍物前来回蹲步
- ✅ 角速度不够强无法甩开
- ✅ 困在"想朝目标去+前方被堵"

**日志标签**：
- `front_obstacle_soft_turn`
- `front_obstacle_hard_turn`
- `front_min / L / R` 数值

**适合**：
- v21在障碍物前蹲步
- 需要更强的避障能力
- 环境中障碍物较多

**参考文档**：`rl_planner_v23_README.md`

---

### v24 (综合版) ⭐ 推荐

**完整控制链**：
```
网络输出
  → 目标角门控（v21）
  → 近目标收束（v22）
  → 障碍绕行（v23）
  → 最终clip
```

**协同优势**：
1. **远离目标 + 空旷** → 保持v21稳定性
2. **远离目标 + 遇障碍** → v23生效
3. **近目标 + 空旷** → v22生效
4. **近目标 + 遇障碍** → v22+v23叠加

**日志标签**：
- 四个维度：`gate / near / orbit / obs`
- 完整覆盖所有控制状态

**适合**：
- 生产环境部署
- 复杂场景（障碍物+精确到达）
- 需要全方位保护

**参考文档**：`rl_planner_v24_README.md`

## 部署建议

### 保守策略（推荐新手）

**第一步：测试基线**
```bash
# 使用v21运行几次
# 记录具体出现什么问题
```

**第二步：针对性升级**
- 只有近目标绕圈 → v22
- 只有障碍蹲步 → v23
- 两个都有 → v24

**第三步：参数微调**
- 先用默认参数测试
- 根据README调优
- 分模块逐个调试

### 激进策略（适合老手）

**直接上v24**
```bash
cp rl_planner_node_v24_full.py \
   ~/catkin_ws/src/rl_planner/scripts/rl_planner_node4.py
```

**优势**：
- 一步到位，全面保护
- 如果某个功能不需要，可以关闭
  ```yaml
  enable_near_goal_controller: false  # 关闭v22
  enable_obstacle_turn_assist: false  # 关闭v23
  ```

**劣势**：
- 参数多，调试复杂
- 出问题时需要分模块排查

## 参数配置策略

### 方案A：完全默认
```bash
# 不修改任何参数，直接运行
roslaunch ...
```
- 适合90%场景
- Zeus-S2 + 543点激光 + 0.5m到达阈值

### 方案B：保守配置
```yaml
# v22部分
near_goal_dist_1: 1.5        # 更早介入
near_goal_v_cap_1: 0.15      # 更保守
near_goal_w_scale_1: 0.3     # 角速度压更多

# v23部分
front_obstacle_dist_thresh: 0.70  # 更早检测
obstacle_turn_w_min: 0.55         # 转向更强
```
- 适合安全第一的场景
- 可能牺牲一定效率

### 方案C：激进配置
```yaml
# v22部分
near_goal_dist_1: 0.8        # 晚介入
near_goal_v_cap_1: 0.25      # 允许更快
near_goal_w_scale_1: 0.7     # 保留更多角速度

# v23部分
front_obstacle_dist_thresh: 0.50  # 晚检测
obstacle_turn_w_min: 0.35         # 转向弱一些
```
- 适合追求效率的场景
- 需要环境相对可控

## 调试技巧

### 快速诊断

**1. 查看日志标签**
```
[RL] ... | gate=X | near=Y | orbit=Z | obs=W | ...
```

| 组合 | 含义 | 下一步 |
|------|------|--------|
| X=none, Y=none, Z=none, W=none | 纯网络控制 | 确认问题是否仍存在 |
| X≠none, Y=none, Z=none, W=none | 只有角度门控生效 | 检查dyaw值是否合理 |
| Y≠none, Z=none, W=none | v22生效 | 检查dist值和速度 |
| W≠none | v23生效 | 检查front_min和L/R |
| Z≠none | 绕圈保护触发 | 说明v22检测到绕圈 |

**2. 单独测试**
```yaml
# 只测v22
enable_near_goal_controller: true
enable_obstacle_turn_assist: false

# 只测v23  
enable_near_goal_controller: false
enable_obstacle_turn_assist: true
```

**3. 参数扫描**
```bash
# 用roslaunch覆盖单个参数测试
roslaunch ... near_goal_dist_1:=1.2
roslaunch ... obstacle_turn_w_min:=0.50
```

## 常见问题

**Q: v24会不会太复杂，反而不稳定？**
A: 不会。v24的两套机制作用于不同场景，不会相互冲突。如果担心，可以先关闭一套测试。

**Q: 我用v21很稳定，需要升级吗？**
A: 如果没有绕圈或蹲步问题，继续用v21即可。v24是为解决特定问题而设计的。

**Q: 能否v22+v23混搭？**
A: 不需要混搭，v24就是v22+v23的完美合并版本。

**Q: 参数太多记不住怎么办？**
A: 只记核心参数：
- v22: `near_goal_dist_*` (距离阈值)
- v23: `front_obstacle_dist_*` (障碍阈值)
- 其他用默认值

**Q: 如何回退到v21？**
A: 备份好v21文件，或者在v24中：
```yaml
enable_near_goal_controller: false
enable_obstacle_turn_assist: false
```

## 总结

**最佳实践路径**：
1. v21建立基线，了解问题
2. v22或v23针对性解决单一问题
3. v24作为生产部署的最终版本
4. 遇到问题时分模块逐个排查

**推荐配置**：
- **90%用户** → v24默认参数
- **追求稳定** → v24保守配置
- **追求效率** → v24激进配置
- **极简主义** → v21
