# 需从训练端获取的信息清单

## 背景

部署端(Zeus-S2 机器人 + ROS Melodic)复现了 ONNX 模型 `model_1200_actor.onnx`
的推理流程,但遇到了一系列行为异常:机器人后退、S 形摆动、右前障碍导致冻结、
目标方位被忽视等。

已经通过分析 9.3 万步训练 rollout (`rollout_steps_esa_on.csv`) 确定:
**训练 env 有一个饱和函数 (piecewise-linear) 把 raw action 压到有限的 vel 范围**,
而部署侧一直用的是错误的线性映射公式。这个信息是通过**拟合**得到的,
但**最可靠的做法是直接从训练代码里拿到原始参数**,避免拟合误差和猜错 esa_on/off。

以下是部署端需要训练端确认或提供的全部信息,按重要性排序。

---

## 一、🔴 最优先 - 必须确认的 3 个问题

这 3 个问题没弄清楚,部署端的映射就不可能和训练完全对齐。

### Q1. 部署用的 ONNX 模型是 esa_on 还是 esa_off 训练出来的?

**背景**:rollout 数据有两个版本,action 分布差异很大。
- `esa_on`:action_w 范围 [-9.56, +9.16], 平均 +0.01, σ=2.82
- `esa_off`:action_w 范围 [-7.77, +7.56], 平均 -0.00, σ=1.45

部署实测 (04202109.bag) 的 action_w 范围是 [-4.87, +9.27], 最大值 +9.27
和 esa_on 的 +9.16 几乎吻合。

**希望确认**:
- `model_1200_actor.onnx` 是 esa_on 训练还是 esa_off 训练?
- 这里 "esa" 代表的是什么机制 (Explicit Safety Action? Env-level Safety?)?
- 如果 esa_on 和 esa_off 用的环境动作映射不同,两套参数是什么?

### Q2. 训练 env 的 `action → vel` 映射公式是什么?

**背景**:训练时 `action_v = +5` 对应 `robot_vel_lin ≈ +1.0 m/s`, 
`action_v = -5` 对应 `robot_vel_lin ≈ -0.086 m/s` (几乎不后退)。
这个饱和映射是部署端必须复刻的。

**希望提供**:
- 训练 env 里 `step(action)` 函数的内部代码 (动作处理部分),
  尤其是从 `action_v/w` 算到 `cmd_vel` 或 `robot_vel_target` 的代码片段
- 如果映射是简单数学公式 (linear / tanh / clip + scale),告知公式和参数
- 如果映射是一个固定函数 (例如一个 Python 函数),希望能拿到函数体

**当前部署侧的拟合结果 (可作为对照验证)**:

esa_on piecewise-linear:
- v 通道: action_v ∈ [-0.21, +1.48] → vel_lin ∈ [-0.086, +1.037]
- w 通道: action_w ∈ [-3.85, +3.43] → vel_ang ∈ [-0.414, +0.368]

esa_off piecewise-linear:
- v 通道: action_v ∈ [-0.21, +1.36] → vel_lin ∈ [-0.142, +0.947]
- w 通道: 近线性, 不饱和, 约 action_w × 0.083 ≈ vel_ang

### Q3. 训练 env 里 LiDAR 的归一化是 ÷几?

**背景**:部署侧一开始用 `÷16` (实际硬件射程),发现机器人整体后退。
分析 normalizer 的 lidar mean=0.333 反推出训练应该用 `÷12`。改成 `÷12` 后问题缓解,
但这是间接证据,没有原代码确认。

**希望确认**:
- 训练 env 的 LiDAR 仿真最大射程 `max_range` 是多少? (推测 12m)
- LiDAR 读数归一化公式是 `normalized = raw / max_range` 吗? 
- 是否有额外 clip (例如 `min(raw, max_range) / max_range`)?
- 超出 `max_range` 的 beam 是怎么处理的? (设为 1.0? 保留 inf? 设为 0?)

## 附录 A:已经在部署侧完成的工作 (供训练端参考背景)

1. **ONNX 验证**: model_1200_actor.onnx 和 model_1200.pt 的权重 bit-exact 一致,
   forward 输出在 1e-6 级别吻合。模型本身没有导出问题。

2. **obs 构造**: 556 维观测向量按 lin3+ang3+grav3+goal4+lidar543 拼接,
   部署实测喂入模型后能得到和训练 log 吻合的 raw action。

3. **Stage 2 归一化**: 已从 ÷16 改为 ÷12 (间接推测), 改后 obs lidar mean
   从 0.28 升到 0.38, 更接近训练 mean 0.333。

4. **_map_action 加固**: 已加 clip + bias 补偿 + 低通滤波,
   但后续用 rollout 数据拟合发现这些都是 workaround, 
   真正的修复是复刻训练饱和函数。

5. **51 例参数化测试**: 用模板 obs + 合成障碍 + 扫参数组合测试了模型,
   确认了 3 个行为异常 (右前 30-45° 冻结, 左右不对称, goal 部分无视),
   这些是模型本身的问题, 部署侧改映射也解决不了。

## 附录 B:当前部署侧的 8 个关键参数 (根据拟合结果,作为训练端对照)

```python
# esa_on piecewise-linear (推荐, 和 rollout 数据吻合)
action_v_xlo = -0.205
action_v_xhi = +1.484
vel_lin_min  = -0.086
vel_lin_max  = +1.037

action_w_xlo = -3.850
action_w_xhi = +3.425
vel_ang_min  = -0.414
vel_ang_max  = +0.368
```

**验证方法**:从训练 env 找一些 (action, vel) 真实样本,代入公式:
```
if action_v <= xlo: vel = vel_min
elif action_v >= xhi: vel = vel_max
else: vel = vel_min + (vel_max - vel_min) * (action_v - xlo) / (xhi - xlo)
```
看是否和实际 env 输出吻合。如果不吻合,就说明映射不是 piecewise-linear,
需要训练端提供真正的公式。
