# 导航研究讨论与决策记录

本页从五篇项目相关的历史AI技术讨论中提炼问题、要求与最终约束，移除了自动摘要、重复代码附录和会话标识。AI回答包含示例和未经运行的建议；以对应源码、训练接口和实验原始记录判定实现状态。完整原始聊天未作为仓库运行证据。

## 2026-06-15 局部规划器适配

原归档相对路径：`01 AI Chats/Claude/强化学习/强化学习模型适配局部路径规划器.md`。

用户报告原模型在8×8m场地训练，直接由激光和终点控制，较大环境容易绕远；希望将其接入全局路径规划。讨论提出局部目标提取、标准插件接口、自适应前瞻、奖励平滑与课程场景等方向。

早期回答把8×8m场地直接理解成8m激光量程，并建议裁剪到8m。后续已明确保留12m，不能用该建议覆盖训练配置。讨论中的360束、360°等属于通用示例，实际主线是181束、270°、三帧。

## 2026-06-19 从节点链到插件

原归档相对路径：`01 AI Chats/Claude/强化学习/节点链条转换为局部规划器插件.md`。

用户明确ROS1 Noetic、move_base、NavfnROS、PPO和ONNX。第一阶段要求保持模型、556维观测及激光/速度/重力/动作处理不变，主要修改目标提供节点，将最终目标改为全局路径前瞻点，再评估标准插件化。

讨论要求过沿路径累计弧长选1.5m点和RViz选点标记。保存的C++实现采用欧氏距离阈值选点，两者应分开。节点与插件都应保留激光历史和修复缓存；“改成类”本身不证明处理等价。

## 2026-06-20 插件完整性与路径接入

原归档相对路径：`01 AI Chats/Claude/强化学习/压缩包插件完整性评价与全局路径规划器接入.md`。

历史静态审查建议修改CMake、参数YAML、头文件和C++实现，包括C++14、目标容差、0.3m/s最大线速、路径剪枝与最近线段投影等。用户确认使用 `/zeus_speed`，并明确反对将12m量程改8m。运行数据又显示该话题可能来自平滑命令，实际反馈来源需要另核查。

用户明确当时还未真正实践；AI也说明环境没有ROS Noetic，无法catkin_make。因此聊天中的“修复”“完整”只说明静态建议或生成文件，不能代表实车验收。

## 2026-06-22 全局路径与局部规划器交互

原归档相对路径：`01 AI Chats/Claude/强化学习/全局路径与局部规划器的交互机制.md`。

讨论区分DWA的速度空间采样与轨迹评分、TEB的位姿/时间优化，以及全局路径裁剪和局部目标的作用。后半段修正了“DWA不取局部目标”的过简表述：目标可参与评分，但不等于候选轨迹直接由该目标生成。

该讨论有助于解释为什么小车策略需要全局路线引导；正式引用时应查对应ROS源码或原论文，历史AI解释不是权威实现说明。

## 2026-06-22 全局路径输出与旧归档

## 可继续研究但尚未验证的方向

速度/曲率自适应lookahead、低通平滑、奖励塑造、近目标停滞惩罚、空旷/走廊/动态障碍课程场景，以及多车能耗优化，都可作为后续研究。相邻动作差分惩罚并不等于严格物理jerk；任何性能提升需有对应训练与消融数据。
