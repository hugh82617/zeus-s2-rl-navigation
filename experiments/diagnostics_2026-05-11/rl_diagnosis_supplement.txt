RL 模型离线诊断 - 补充分析报告
===============================================================================

【重要发现】离线推理与实际部署存在显著差异
===============================================================================

1. 离线推理结果 (基于简化模型前向传播):
   - raw_v 范围: [0.00, 0.07] → 映射后 v: [0.15, 0.17] m/s
   - raw_w 范围: [0.00, 0.89] → 映射后 w: [0.00, 0.44] rad/s
   - 线速度饱和率: 0.0%
   - 角速度饱和率: 0.0%

2. 实际部署结果 (summary.txt记录):
   - 线速度范围: [-0.20, 0.50] m/s (触及限幅)
   - 角速度范围: [-0.50, 0.50] rad/s (触及限幅)
   - summary.txt第19-30行显示:
     * linear_x = 0.50 (饱和)
     * angular_z = -0.50 (饱和)
   - 持续多帧处于饱和状态

3. 差异分析:
   ⚠ 离线推理显示模型输出非常保守 (v最大仅0.07)
   ⚠ 实际部署显示模型输出非常激进 (频繁饱和)
   
   这说明:
   - 简化的前向推理没有正确复现模型行为
   - 可能缺少关键的网络层、激活函数或normalization
   - 需要完整的网络定义才能进行准确的离线分析

4. 缺少的关键组件 (导致离线推理不准确):
   ✗ 完整的Actor网络类定义
   ✗ Observation normalization参数 (running_mean, running_var)
   ✗ 正确的网络层数和激活函数配置
   ✗ 可能的LayerNorm/BatchNorm层
   ✗ Action scaling参数
   
5. 基于实际部署数据的分析结论:

   【问题1: 动作输出频繁饱和】 ⚠⚠⚠ 严重问题
   证据: summary.txt显示速度频繁触及±0.5限幅
   影响: 
   - 模型期望更大的动作空间
   - 控制不够平滑,容易导致震荡
   - 说明部署端限幅可能与训练端不一致
   
   【问题2: 接近目标时的旋转行为】 ⚠⚠ 中等问题
   证据: 
   - 距离<1m时有14帧观测
   - 离线推理显示该阶段raw_w均值=0.60 (即使离线推理不准,相对趋势仍有参考价值)
   - 模型在接近目标时仍输出较大角速度
   影响: 
   - 路径效率降低 (0.603)
   - 在目标附近可能出现旋转、震荡
   
   【问题3: 缺少目标最终朝向控制】 ⚠⚠ 设计限制
   证据: obs[12]=dyaw=atan2(dy,dx) 只表示目标方向
   影响:
   - 无法控制到达目标后的最终朝向
   - 只适合点到点导航,不适合定点定向
   
   【问题4: 路径效率偏低】 ⚠ 综合问题
   证据: 路径效率0.603,总路径7.56m,直线5.00m
   可能原因:
   - 模型决策质量 (训练不足)
   - sim-to-real差异 (摩擦力、传感器噪声)
   - LiDAR归一化 (基本正常,最大0.97)
   - 动作饱和导致控制不平滑

===============================================================================
修改建议 (基于实际部署数据,按优先级排序)
===============================================================================

【最高优先级】检查并修复动作映射配置
   
   实际问题: 速度频繁触及±0.5限幅,说明模型输出非常激进
   
   需要检查:
   1. 训练端的动作范围是什么? 
      - 检查训练代码中的 action_low, action_high
      - 检查是否使用了特殊的action_scaling
      
   2. 部署端的映射公式是否正确?
      当前公式: v = -0.2 + (raw_v+1)*0.5*0.7
                w = -0.5 + (raw_w+1)*0.5*1.0
      
      如果训练端使用不同的映射,会导致部署端行为异常
      
   3. 是否存在额外的action bias?
      - 检查是否有angular bias compensation
      - 检查是否有normalize/denormalize步骤
      
   验证方法:
   - 对比训练代码中的action映射逻辑
   - 检查是否有PPO wrapper的action scaling
   - 确认raw_action是否经过tanh还是clip

【高优先级】确认观测向量构造完全一致

   需要验证:
   1. obs[0:6] 速度是base_footprint系还是map系?
   2. obs[9:13] 目标是局部坐标还是全局坐标?
   3. obs[13:556] LiDAR堆叠顺序是[t0,t1,t2]还是[t2,t1,t0]?
   4. LiDAR归一化是÷12还是其他值?
   
   当前检查结果:
   - LiDAR最大值0.97,基本符合÷12假设 ✓
   - 重力固定为[0,0,-1] ✓
   - 但无法确认其他维度的细节

【中优先级】增加目标附近停止逻辑

   在rl_local_goal_provider中增加:
   ```python
   if goal_distance < 0.3:
       # 提前停止RL控制,避免在目标附近旋转
       stop_rl_control()
   ```
   
   理由:
   - 接近目标时模型仍输出较大角速度
   - 导致路径效率降低
   - RL更适合远距离导航,近距离可以用简单控制

【中优先级】如需定点定向,需修改obs定义

   当前: dyaw = atan2(dy, dx) (目标方位)
   修改: 增加 goal_yaw_error = goal_yaw - robot_yaw (目标姿态误差)
   
   或者: RL只负责到达附近,最后朝向由简单PID控制

【低优先级】考虑retraining改进

   - 使用tanh约束action,避免饱和
   - 镜像数据增强
   - 场地尺寸随机化
   - 初始速度随机化

===============================================================================
与DWA的客观对比
===============================================================================

DWA局部规划器:
  优点:
  - 控制逻辑明确,数学基础扎实
  - 稳定性强,不依赖训练数据
  - 对环境变化鲁棒
  - 参数调节直观
  
  缺点:
  - 计算开销大 (轨迹采样+打分)
  - 速度较慢,路径保守
  - 难以处理复杂约束
  
RL局部规划器:
  优点:
  - 推理快 (单次前向传播)
  - 决策灵活,可以学习复杂策略
  - 响应快,动作连续
  
  缺点:
  - 高度依赖训练数据分布
  - 对输入一致性极其敏感 (归一化、动作映射、obs顺序)
  - sim-to-real差异明显
  - 调试困难,黑盒性质
  - 需要大量训练时间和计算资源
  
工程建议:
  - DWA作为稳定基线,用于生产环境
  - RL用于展示智能决策和研究创新
  - 当前RL路径效率0.60 vs DWA可达0.75+
  - 如果RL无法显著超越DWA,工程价值有限

===============================================================================
总结
===============================================================================

由于缺少完整的网络定义,离线推理无法准确复现模型行为。但基于实际部署数据
(summary.txt)可以明确判断:

1. 【严重问题】动作输出频繁饱和
   → 最可能原因: 训练端与部署端动作映射不一致
   → 需要立即检查训练代码的action配置

2. 【中等问题】接近目标时旋转调整
   → 原因: 模型在近距离仍输出较大角速度
   → 建议增加提前停止逻辑

3. 【设计限制】无法定点定向
   → 原因: obs中只有方位角,没有姿态误差
   → 如需此功能,需重新训练或增加后处理

4. 【综合问题】路径效率偏低 (0.60)
   → 综合原因: 模型质量、动作饱和、sim-to-real差异
   → 需要综合改进

建议的调试流程:
1. 获取训练代码,对比action映射逻辑 (最高优先级)
2. 确认obs构造的每个维度 (高优先级)
3. 增加目标附近停止逻辑 (快速改进)
4. 考虑是否值得继续投入,还是回退到DWA (工程决策)
